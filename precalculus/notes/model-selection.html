A function model is a function chosen to describe a real situation: the height of a beanbag, the cost of a phone plan, the volume of a box. Before you can build one, you have to choose its type. This page is about that choice, and about saying plainly what the model takes for granted.

Two sources of evidence: the data and the context

You choose a model type by asking two questions. What pattern do the numbers show? What does the situation itself suggest? A good choice agrees with both.

The numbers speak through their changes. Over equal input steps:

Pattern over equal input stepsWhat it meansModel type
First differences constantThe rate of change is constantLinear
Second differences constantThe rate of change changes at a constant rateQuadratic
Third differences constantThe changes in the rate of change are constantCubic
Different behavior on different intervalsOne rule does not describe the whole situationPiecewise-defined

The context speaks through what the quantity measures. An area is a product of two lengths, so it suggests a quadratic. A volume is a product of three lengths, so it suggests a cubic. A height that rises to one maximum and falls back symmetrically suggests a quadratic. A price that is flat up to a limit and then charges per unit suggests a piecewise-defined model.

Worked example 1. A beanbag is tossed upward from a hand 66 feet above the ground. Its height, in feet, at t=0,0.5,1,1.5,2t = 0, 0.5, 1, 1.5, 2 seconds is 6,18,22,18,66, 18, 22, 18, 6. Choose a model type.

The inputs go up by 0.50.5 each time, so the steps are equal. First differences (later minus earlier): 12,4,−4,−1212, 4, -4, -12. These are not constant, so a linear model is out.

Second differences: 4−12=−84 - 12 = -8, −4−4=−8-4 - 4 = -8, −12−(−4)=−8-12 - (-4) = -8. Constant, so a quadratic model fits.

The context agrees: a tossed object rises to one highest point and falls back.

Check the equal steps first. If the inputs are 0,1,3,40, 1, 3, 4, the gaps are not equal, and comparing raw differences tells you nothing until you divide each by the length of its step, which gives the average rate of change on each interval.

More points do not mean a better model

Through any n+1n + 1 points with different inputs, there is a polynomial of degree at most nn that hits every point. Five points can always be matched by a degree-44 polynomial. That does not make it the right model. Between and beyond the data it can turn up and down for no reason the situation supports (compare the smooth quadratic in the figure). Choose the simplest type that matches the pattern and the context.

Assumptions and the domain the context allows

Every model takes some things for granted. Saying what they are is part of the answer, and the exam asks for it in words.

  • Restricted domain. Only some inputs make sense. Time starts at 00. A beanbag model stops when the beanbag lands, where h(t)=0h(t) = 0. A cut from a 1212-inch sheet must be less than 66 inches if two cuts come out of each side.
  • Restricted range. Only some outputs make sense: no negative heights, no fractional people, no soup colder than the room it sits in.
  • Built-in assumptions. A box formula that uses the full 12−2x12 - 2x assumes the sheet has no thickness. A linear cooling model assumes the soup cools at the same rate the whole time, which real soup does not.

Worked example 2. T(m)=90−4mT(m) = 90 - 4m models the temperature of soup, in degrees Celsius, mm minutes after it is set in a 2222-degree room. What domain does the context allow?

Soup cools toward room temperature and never drops below it. Solve 90−4m=2290 - 4m = 22: 4m=684m = 68, so m=17m = 17.

After 1717 minutes the model gives temperatures below 2222 degrees, which cannot happen. Use the model for 0≤m≤170 \le m \le 17, and say why: "after m=17m = 17 the model predicts soup colder than the room."

When you explain a restriction, name the bound and the reason, using the numbers. "The domain is 0≤m≤170 \le m \le 17 because the soup cannot cool below the room's 2222 degrees" earns credit. "Time cannot be negative" alone does not explain the upper end.

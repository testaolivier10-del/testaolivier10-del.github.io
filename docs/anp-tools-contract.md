# A&P tools and app pages: the runtime contract

For whoever builds a tool or an app page. Read `docs/anp-spec.md` sections 8, 10–14 and 17 and
`docs/anp-phase1-architecture.md` first.

## What you write, and what you must not touch

| You write | Path |
|---|---|
| the page's script | `anatomy-physiology/assets/<script>` as named in `anatomy-physiology/data/pages.json` |
| the page's stylesheet | `anatomy-physiology/assets/<css>` as named there |
| a tool's content | `anatomy-physiology/data/tools/<slug>.json` |
| a validator for that content | `scripts/lib/anp-tool-checks/<slug>.mjs`, exporting `check(data, map)` that returns an array of error strings |

- **Pages:** the page shell (head, header, SEO, breadcrumbs, `<div id="app">`, script tags) is
  generated by `scripts/build-anp.mjs` from `pages.json`. Do not write HTML pages. Run
  `node scripts/build-anp.mjs` to regenerate them.
- **Scripts:** a script runs after the shared ones, deferred. Mount into `#app`, and read
  `#app[data-src]` for your content file's URL.
- **Off limits:** shared files (`assets/*`, `anp-core.js`, `anp-questions.js`, `anp.css`, the
  generator, other tools' files) are not yours to edit. If you need a change in one, describe
  it in your final report.

## Runtime APIs (already on every page)

- **`window.AnpCurriculum`:** `{ chapters[], topics[], core[], coreCounts }`. Each topic has
  `{ id, title, chapter, course, kind, core, n, built, qn }`.
- **`window.AnpTools`:** `[{ slug, name, blurb }]`.
- **`window.ANP_BASE`:** the relative path from this page to `anatomy-physiology/`.
- **`window.AnpCore`:**
  - `record(itemId, correct, { topic, core, level, diff, src })`: records one answer. It awards
    XP, updates mastery and puts misses into the review queue.
  - `toolResult(kind, items, { xp })`: records a batch. `items` is
    `[{ id, correct, topic, core, level, diff, group }]`, and `group` feeds the dashboard's
    accuracy-by-group rows (a system, a level).
  - `toolStats(kind)`: returns `{ n, c, by }`.
  - Mastery: `topicMastery(id)`, `chapterMastery(id)`, `coreMastery(id)` and `overallMastery()`
    each return `{ value 0..1, answered, ... }`. `weakest(n)` and `weakestCore(n)` rank them.
  - Review: `reviewQueue(limit)` returns the item ids that are due. `missed()` returns item ids
    whose latest answer was wrong. `load()` gives the raw store.
  - `event(name, data)`: analytics (Umami). Use the names below.
  - `allowed(feature)`: premium gating later (spec section 14). Call it before anything the spec
    says may be gated. It returns true for now.
  - `pct(v)`: formats a value as a percentage.
- **`window.AnpQuestions`:** `render(q, host, { n, record, onAnswer, exam })` renders and grades
  any bank question. `shuffle(arr)`.
- **Question bank:** `AnpCore.loadBank(ANP_BASE, { chapters, why })` resolves to an array of
  questions with `why` and `variables` merged in, ready for `AnpQuestions.render`. The bank is
  split by chapter: `assets/bank/<chapter>.json` (questions without explanations) and
  `assets/bank/<chapter>-why.json` (`{ id: { why, variables } }`). `chapters` defaults to every
  chapter with a built topic; `why: false` skips the explanation files.
- **`window.LevlReport.button('anp', itemId)`:** "Report a problem" HTML. Every scored item
  gets one.

## Item ids

Tool items are recorded like questions, so misses reach review. The id format is
`<tool>:<content id>:<item id>`, stable forever, e.g. `predict:hemorrhage-l4:heart-rate`.

## Standards every tool meets

- **Keyboard and phone** (spec section 17): no drag-only interaction. Offer buttons, select
  lists or tap-to-place. Visible focus. Nothing wider than a 360 px phone screen without its own
  scroll container. No layout shift: reserve space before content loads.
- **Offline:** read content only from same-origin files. The service worker caches them on visit.
- **Visual language** (spec section 6): figures use `anp.css` classes only (`o2`, `deo2`, `symp`,
  `para`, `aff`, `eff`, `hi`, `lo`, `memb`, `shape`, `accent`, and `causes` or `flows` for
  arrows). Put an SVG inside an element with class `anp-fig`. Labels go on the figure, with no
  legends, and every SVG has `role="img"` and an `aria-label`.
- **Content is data:** every item is tagged with `topic` (a map topic id), `core` (core concept
  ids), `level` and, where it targets one, `misconception`. Content follows the ordering rule:
  an item for topic X uses only terms taught in X or earlier. Check that the tagged topic makes
  sense.
- **Explanations:** every item explains itself causally. Never refer to options by letter or
  position.
- **Cleared material only:** OpenStax figures must be registered and cleared (spec section 2).
  Otherwise use your own SVG. No NC or SA material anywhere.
- **Pilot scope:** Foundations (topics 1–33) and Cardiovascular (topics 95–110). The planned
  items per chapter are listed in `docs/anp-dependency-map.json` under `chapters[].tools`.
